This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

SSM (Signal State Module) is STM32G473-based embedded firmware for controlling and monitoring traffic signal lights (Red/Yellow/Green) via CAN bus. It is part of a larger TEKNOTEL traffic management system alongside PSM and CP modules.

## Build Commands

This project uses CMake with Ninja. Two build targets exist: STM32 firmware and Host unit tests.

```bash
# STM32 firmware (arm-none-eabi-gcc)
cmake --preset STM32-Debug   && cmake --build --preset STM32-Debug
cmake --preset STM32-Release && cmake --build --preset STM32-Release

# Host unit tests (x86-64, requires gcc + gcovr)
cmake --preset Host-Test && cmake --build --preset Host-Test
cd build/Host-Test && ctest --output-on-failure

# Or use the scripts
./Tools/Scripts/build-arm.sh [STM32-Debug|STM32-Release]
./Tools/Scripts/build-test.sh   # builds + runs tests + coverage

# Flash to hardware
./Tools/Scripts/flash.sh [STM32-Debug|STM32-Release]

# Docker (no local toolchain needed)
docker compose -f Tools/Docker/compose.yml run build-arm
docker compose -f Tools/Docker/compose.yml run build-test
```

Output: `build/{STM32-Debug,STM32-Release}/SSM.elf`

Preset definitions are in `CMakePresets.json`. The toolchain files are `cmake/gcc-arm-none-eabi.cmake` (STM32) and `cmake/host-gcc.cmake` (Host). STM32CubeMX-generated sources are in `cmake/stm32cubemx/CMakeLists.txt` and should not be manually edited.

## Architecture

### FreeRTOS Tasks

The system has 5 tasks created in `Core/Src/app_freertos.c`:

| Task | File | Role |
|------|------|------|
| `MaitenanceTask` | — | Watchdog (IWDG) refresh, monitors all other tasks for failures via `MaintenanceEvent` flags |
| `CANMsgParserTask` | `Tasks/Src/can_msg_parser.c` | Parses CAN RX commands, drives GPIO signal outputs, manages flash signal configs |
| `CANMsgSenderTask` | `Tasks/Src/can_msg_sender.c` | Sends voltage/current telemetry CAN TX messages |
| `MeasurementTask` | `Tasks/Src/measurement.c` | ADC-based voltage/current measurement for 4 signal groups, monitors output state |
| `StorageTask` | `Tasks/Src/storage.c` | Serializes all flash read/write operations from a request queue |

### Signal Output Structure

- 4 signal groups, each with 3 outputs: Red, Yellow, Green → 12 total GPIO outputs
- Each output tracks: on/off counters, active, on, and flashing flags
- Group IDs and CAN IDs are determined at runtime from card ID pins (GPIOC/GPIOD: ID0–ID3)

### CAN Protocol (11-bit standard IDs)

- `0x040–0x041` — CP → SSM signal output commands
- `0x050–0x057` — SSM → supervisory voltage/current measurements (indexed by card ID)
- `0x069–0x06A` — PSM flash sync messages
- `0x0B0–0x0B1` — CP → SSM flash signal configuration

### Inter-Task Communication

- **Queues:** `CANRxReqsQueue`, `CANTxReqsQueue`, `StorageReqsQueue`
- **Mutexes:** `CurrentMutex` (ADC current data), `OutputStatesMutex` (signal output state)
- **Event Flags:** `MaintenanceEvent` — each task signals its health; maintenance task resets watchdog only when all flags are set
- **Memory Pools:** Fixed-size pools for queue request structs (avoids heap fragmentation)

### Key Shared Headers

- `Core/Inc/utilities.h` — extern handles for all tasks, queues, mutexes, memory pools; common macros
- `Core/Inc/can_util.h` — CAN message IDs, signal output enums, request/response structs

### Peripheral Overview

- **FDCAN1/FDCAN2** (`Core/Src/fdcan.c`) — dual CAN controllers
- **ADC1/ADC2** (`Core/Src/adc.c`) + **DMA** — current sensing via DMA transfers, triggered by TIM3
- **TIM2** — grid frequency measurement
- **TIM4** — periodic output state monitoring
- **Flash** (`Core/Src/flash.c`) — internal STM32 flash for persistent signal configuration
- **IWDG** — hardware watchdog; reset if maintenance task misses its deadline (max 3000 ms, 3 failures)

### Memory

- FreeRTOS heap: 10 KB (static allocation mode, `configSUPPORT_STATIC_ALLOCATION = 1`)
- Tick rate: 1000 Hz
- Linker script: `STM32G473XX_FLASH.ld`

## CubeMX-Generated Code

Files under `Core/Src/` for peripherals (`adc.c`, `fdcan.c`, `gpio.c`, `tim.c`, `dma.c`, `iwdg.c`, `crc.c`) and `Core/Src/main.c` are partially generated by STM32CubeMX (`SSM.ioc`). Application logic lives in `Tasks/` and the custom sections of `main.c`. Re-running CubeMX will overwrite peripheral init files — keep application code out of generated files.
