# Repository Guidelines

## Project Overview

**SSM (Signal State Module)** is STM32G473-based embedded firmware for controlling and monitoring traffic signal lights (Red / Yellow / Green) via CAN bus. It is part of the TEKNOTEL traffic-management system alongside PSM, CPM/CP, and CPM/MP.

## Project Structure & Module Organization

- `App/Domain/` — pure C11 domain logic (host-testable, HAL/RTOS-free).
- `App/Adapters/STM32/` — production adapters (e.g. `AdcCurrentAdapter`).
- `Tasks/` — FreeRTOS task implementations (one `.c` per task).
- `Core/` — STM32CubeMX-generated startup / peripheral init. Edit only inside `/* USER CODE BEGIN/END */` guards.
- `Tests/Unit/` — Unity host tests.
- `Tools/` — Docker + formatter helpers.
- `Drivers/` + `Middlewares/` — STM32G4 HAL and FreeRTOS vendor code; do not modify.
- `cmake/` — toolchain wrappers and CubeMX CMake glue (`cmake/stm32cubemx/CMakeLists.txt` — not manually edited).

## Build, Test, and Development Commands

CMake + Ninja. Two build targets: STM32 firmware and host tests.

```bash
# STM32 firmware (arm-none-eabi-gcc)
cmake --preset STM32-Debug   && cmake --build --preset STM32-Debug
cmake --preset STM32-Release && cmake --build --preset STM32-Release

# Host unit tests (x86-64, requires gcc + gcovr)
cmake --preset Host-Test && cmake --build --preset Host-Test
(cd build/Host-Test && ctest --output-on-failure)

# Helper scripts
./Tools/Scripts/build-arm.sh [STM32-Debug|STM32-Release]
./Tools/Scripts/build-test.sh   # build + test + coverage
./Tools/Scripts/flash.sh  [STM32-Debug|STM32-Release]

# Docker (mirrors CI)
docker compose -f Tools/Docker/compose.yml run build-arm
docker compose -f Tools/Docker/compose.yml run build-test
```

Output: `build/{STM32-Debug,STM32-Release}/SSM.elf`. Preset definitions in `CMakePresets.json`; toolchain files `cmake/gcc-arm-none-eabi.cmake` and `cmake/host-gcc.cmake`.

## FreeRTOS Tasks

Five tasks created in `Core/Src/app_freertos.c`:

| Task | File | Role |
|------|------|------|
| `MaintenanceTask` | (inline) | IWDG refresh, watches all other tasks via `MaintenanceEvent` flags |
| `CANMsgParserTask` | `Tasks/Src/can_msg_parser.c` | Parses CAN RX commands, drives GPIO signal outputs, manages flash signal configs |
| `CANMsgSenderTask` | `Tasks/Src/can_msg_sender.c` | Sends voltage/current telemetry CAN TX frames |
| `MeasurementTask` | `Tasks/Src/measurement.c` | ADC-based voltage/current measurement for 4 signal groups |
| `StorageTask` | `Tasks/Src/storage.c` | Serialises all flash read/write requests from a queue |

## Signal Output + CAN Protocol

4 signal groups × 3 outputs (Red/Yellow/Green) = 12 GPIO outputs. Each output tracks on/off counters plus `active`, `on`, `flashing` flags. Card/CAN IDs are read at runtime from ID0–ID3 pins on GPIOC/GPIOD.

CAN (11-bit standard IDs):
- `0x040–0x041` — CP → SSM signal output commands
- `0x050–0x057` — SSM → supervisory voltage/current measurements (indexed by card ID)
- `0x069–0x06A` — PSM flash sync
- `0x0B0–0x0B1` — CP → SSM flash signal configuration

## Inter-Task Communication

- **Queues**: `CANRxReqsQueue`, `CANTxReqsQueue`, `StorageReqsQueue`.
- **Task / ISR shared state**: ADC current data is double-buffered in `AdcCurrentAdapter` (lock-free, `__DMB` ordering). Signal-output sample counters are protected by a brief `taskENTER_CRITICAL` on the task side; the TIM4 ISR runs mutex-free because `osMutex` from ISR is UB.
- **Event flags**: `MaintenanceEvent` — each task signals its health; maintenance task refreshes the watchdog only when all flags are set.
- **Memory pools**: fixed-size pools for queue request structs (avoids heap fragmentation).

## Key Shared Headers

- `Core/Inc/utilities.h` — extern handles for all tasks, queues, mutexes, memory pools; common macros.
- `Core/Inc/can_util.h` — CAN message IDs, signal output enums, request/response structs.

## Peripheral Overview

- **FDCAN1 / FDCAN2** (`Core/Src/fdcan.c`) — dual CAN controllers.
- **ADC1 / ADC2** (`Core/Src/adc.c`) + **DMA** — current sensing, TIM3-triggered.
- **TIM2** — grid frequency measurement.
- **TIM4** — periodic output state monitoring.
- **Flash** (`Core/Src/flash.c`) — internal STM32 flash for persistent signal config.
- **IWDG** — hardware watchdog; reset if maintenance task misses deadline (max 3000 ms, 3 failures).

Memory: FreeRTOS heap 10 KB (static allocation, `configSUPPORT_STATIC_ALLOCATION = 1`), tick rate 1000 Hz. Linker script: `STM32G473XX_FLASH.ld`.

## CubeMX-Generated Code

Files under `Core/Src/` for peripherals (`adc.c`, `fdcan.c`, `gpio.c`, `tim.c`, `dma.c`, `iwdg.c`, `crc.c`) and `Core/Src/main.c` are partially generated by STM32CubeMX (`SSM.ioc`). Application logic lives in `Tasks/` and USER-CODE sections of `main.c`. Re-running CubeMX overwrites peripheral init files — keep application code out of generated files.

## Coding Style & Naming Conventions

C11 throughout. Formatting follows the repo Uncrustify MISRA config (2-space indent, Allman braces, explicit braces on every control body, pointer star attached to variable name, no `//` comments).

Naming follows the system-wide rules in the root `CLAUDE.md` / `AGENTS.md` § "Naming Conventions": `PascalCase_t` types, `PascalCase_e` enums, `camelCase` variables/fields/params, `SCREAMING_SNAKE_CASE` macros, `g_` / `s_` for scope, **no Hungarian prefixes**.

**Do not reintroduce** the legacy prefixes previously used here: `b` (uint8_t), `s` (uint16_t), `l` (uint32_t), `f` (float / flag), `p` (pointer), `tS` (struct typedef), `tE` (enum typedef), `tU` (union), `S` / `U` (struct/union instance). Type information comes from the declaration, not the identifier.

**Migration status: SSM is not yet migrated.** All of those legacy prefixes are still present in existing files. Follow the new convention for new code; rename opportunistically when touching a legacy file. Union-typedef idioms from the old `tU` scheme become `SomeName_t` — the typedef suffix is `_t` whether the underlying aggregate is a struct or a union.

CubeMX-generated locals inside `Core/` HAL init blocks (e.g. `sConfig`, `sMasterConfig`) are regenerated on each `.ioc` export and must be left alone.

## Testing Guidelines

Unit tests in `Tests/Unit/` using Unity. Name test files `Test_<Module>.c`; each must define its own `main()` with `UNITY_BEGIN()`, `RUN_TEST(...)`, `UNITY_END()`. Register via `Add_Unity_Domain_Test` in the CMake wiring. The `App/Domain/` line-coverage gate is enforced at 80 % (`gcovr.cfg`).

When logic in `Tasks/` becomes hard to test on hardware, extract the computation into `App/Domain/` and mock-adapter-test it on host first.

## Commit & Pull Request Guidelines

Short, imperative commit subjects. PRs should state which build targets were exercised (`STM32`, `Host`, both), include `ctest` output on domain-logic changes, and attach coverage output when behavior shifts.

## CI/CD

CI lives at the repo root in `/CPU4v1/.github/workflows/`:

| Workflow | Trigger | What it does |
|---|---|---|
| `ssm-build.yml` | push/PR to `main` touching `SSM/**`, `workflow_call` | STM32-Debug + STM32-Release firmware; uploads `.elf` + `.map` (30 days) |
| `ssm-test.yml` | push/PR touching `SSM/**`, `workflow_call` (with `min_line_coverage` input) | Host-Test build, ctest, full + Tasks-scoped gcovr reports (7 days) |
| `ssm-release.yml` | tag `ssm-v*.*.*` | Calls build + test, generates `.bin`, creates GitHub Release |

## Vendor MIB Maintenance (1.3.6.1.4.1.59748)

SSM does not serve SNMP itself, but SSM status reaches the CP SNMP agent over the field-bus and surfaces under the Teknotel enterprise arc `1.3.6.1.4.1.59748`. The canonical `.mib` (vendor "Teknotel Elektronik") lives at `../CPM/CP/Docs/TEKNOTEL-CPU4-MIB.mib`. OID arc shape: `teknotel .59748 → transportation .4 → devices .2 → cpu4 .1 → { unit .3, channel .8, cpMpLink .20, driverModule .21 }`.

**Update that `.mib` in the same commit** whenever SSM work changes:

- The 16-bit SSM status-word bit layout — sole varbind of `teknotelDriverModuleMissingTrap` (specific-trap 2, `.59748.0.2`), carried at `driverModuleStatus` (`.59748.4.2.1.21.1`). Any new status bit must be documented in the MIB `DESCRIPTION`.
- The per-channel fault flags SSM contributes to `CpMpFaultChannelFlags_t` (surface as `channelFaultFlags` rows under `.59748.4.2.1.8.2.1.2`) — `RED_FAIL`, `DARK`, `LAMP_OPEN`, `LAMP_EXTERNALLY_DRIVEN`.
- The trigger condition that causes CP to emit `teknotelDriverModuleMissingTrap`.

Do not invent new enterprise OIDs from SSM — new objects must be added on the CP side via `CPM/CP/App/Domain/NTCIP/MibVendor59748/` (one file per functional group) and simultaneously in the `.mib`.
